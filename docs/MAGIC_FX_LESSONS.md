# 마법 이펙트 제작 레슨런 — V241/V242 사용자 결정

2026-10-23 사용자는 캡처 프레임의 빈 픽셀과 타일 밖 잘림을 반복 보고했고, 후속 4써클 작업에도 이 교훈을 적용하라고 지시했다. 다음 마법 작업은 이 파일을 먼저 읽는다.

1. 영상은 마법의 정체·형태·색·움직임을 확인하는 근거다. 영상에서 배우·체력바를 잘라내는 작업부터 시작하지 않는다. 보존된 원본 클라이언트에서 일치하는 EPF/EFA 프레임을 먼저 찾고 영상/기존 이름표 자료와 직접 대조한다. 비슷하다는 이유만으로 다른 마법에 연결하지 않는다. 원본이 없으면 그 사실을 남기고, 가려진 픽셀을 복구했다고 주장하지 않는다.
2. 원본 바이트·팔레트·기준점·프레임 순서·해시를 보존한다. EPF efctNNN.tbl은 발 기준점이며 시간표가 아니다. effect.tbl은 재생 프레임 순서다. EFA header에는 실제 프레임 간격과 blend 종류가 있다. 원본 시간과 영상에 맞춘 프로젝트 시간을 구분한다.
3. 각 프레임의 원본 발 기준점을 적용한 뒤 전체 프레임의 합집합 캔버스를 만든다. 프레임 밖으로 뻗는 입자·상승부·아래쪽 섬광도 포함한다. 타일 크기에 이펙트를 맞추지 않는다. 투명 여백만 제거할 때도 원래 위치로 복원해 모든 원본 픽셀의 동일성을 검사한다. 샘플링 여백을 둔다.
4. 배우/HP를 지우는 사각형 마스크, 좁은 타원/원 영역, 강한 색 임계값, 작은 연결 성분 일괄 삭제는 실제 이펙트도 없앤다. V237/V239에서 관측된 구멍·잘린 외곽의 원인이므로 완전한 원본 프레임에는 적용하지 않는다. 검정 선을 SCREEN으로 지우는 것도 피한다. EFA2 self-alpha는 SCREEN, 어둠의각인 EPF는 원본 palette alpha NORMAL로 구분한다.
5. EFA RGB565는 row pitch와 visible frame width를 구분해서 읽는다. 행 패딩을 그림으로 취급하지 않는다. 희미한 nonzero 색도 보존한다. 원본 header interval, pivot, 전체 RGB 복원과 atlas 경계 여백을 자동 검증한다. 지원하지 않는 blend를 임의로 비슷하게 치환하지 않는다.
6. 단일/전체 마법은 대상 규칙과 시각 소스를 분리한다. 전체 마법은 화면 안의 살아 있는 각 대상에 1회, 단일은 선택 대상에 1회. 같은 이펙트는 동일 채널/atlas를 공유하며 복제해서 디코딩하지 않는다. MP는 시전당 1회이고 접촉 때 사망/화면 밖 대상은 다시 확인한다.
7. 원본 비교 + 실제 GameView 시전 화면을 모두 본다. alpha 픽셀 수, 파일 존재, 빌드 성공만으로 외형 PASS라 하지 않는다. 큰 이펙트가 주변 타일로 나가는 장면과 각 프레임의 완전한 픽셀 렌더를 검사한다. 원본의 의도된 투명한 중앙/소멸 디더링은 누락으로 메우지 않는다.
8. 변경 기능과 직접 영향을 받는 경로만 검증한다. V242는 4circle 단일/전체8개, 접촉 recheck, source/frame/interval/pivot/외곽, 기본4/승급14 접촉과 인접 contact를 검사한다. 수치·습득·맵·몬스터·저장은 수정하지 않는다. 전체 회귀/휴대폰 수용과 범위 제한 호스트 검증을 구분한다. exact source/run/artifact/hash를 확인한 APK만 전달하며 문서 커밋을 APK 소스로 재라벨하지 않는다.

검증된 예: V241 source296656066627ef40d3a5210ca2bc70e489bc3907/run39868184395. V242 EFA236/252/242/239는 이번080624 영상과 대조한 수/토/풍/화 원본이다. 이전에 잘못 연결하거나 마스킹한 캡처가 있다는 이유로 그것을 원본 기준으로 삼지 않는다. 다른 마법·시대의 모든 원본까지 검증됐다는 의미는 아니다.

원본 파일도 실제 검수를 생략하지 않는다. V242 EFA252 frame1에는 이펙트에서 떨어진 uniform0x18e3가로scanline240px가 있었다. 원본은 보존하고, 영상에 없고 다음20행이 비어 있는 해당row0 하나만 명시ADAPTED display correction으로 제거했다. 다른프레임·입자에는일괄mask를적용하지않으며 원본hash와 displayhash를둘다기록한다.
