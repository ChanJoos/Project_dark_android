# V97 mobile quest journal

User request: matching quest icon next to upper-right Skills, all quests and receivable ones, searched mobile quest UI, compact quick objective with direct travel, coherent progression and a phone-downloadable APK.

Research: official Black Desert Mobile Remaster Season Guide, https://www.world.blackdesertm.com/Ocean/Wiki?wikiNo=2177 (Basic Interface / Season Pass: upper-right menu, quest list, progress and goal navigation). Reference screenshots https://s1.blackdesertm.com/GL/forum/BDM/Upload/WIKI/ad3ae3b904520260315223434025.png and https://s1.blackdesertm.com/GL/forum/BDM/Upload/WIKI/d0f4a9a8ced20260315223450160.png. Adapted interaction/layout only; no borrowed art.

QuestJournalModel projects the original prologue and GrowthQuest2 domain state. It loads all 9 canonical Master quests as region-locked entries, alongside the 2 playable quests and existing Hans forest travel. Master READY is a design status, not a runtime acceptability signal. Planned quests show source names/objectives/level/prerequisites and cannot accept, navigate or grant rewards. Hans is an ADAPTED travel milestone with no invented reward. Its visited flag persists in project_dark_journal_v1 after a real forest entry following the growth chain; it cannot write when the primary save is unwritable.

QuestJournalWindow owns filters/list selection/paging/drag input and brown/gold drawing. The right icon is logical x808 plus wide HUD offset, next to unchanged Skills x770; its radius16/style matches the rail. List center shifts with the expanded viewport. Modal input blocks world actions. Current quest is selected on open; all states remain inspectable. CTA text maps AVAILABLE to accepting NPC, ACTIVE to objective, REPORT to reporting NPC, and disables LOCKED/COMPLETE. Domain handlers still perform NPC acceptance/report and atomic rewards. Quick quest is title/status plus short goal/count in the existing 250x40 bounds; its first touch dispatches actual navigation. The current goal follows prologue -> growth -> Hans, hides after completed travel, and next quest descriptions explain connections.

Existing WorldRuntimeAdapter handles routes, walls, NPC approaches, inn entry and exit. A pending inn entry continues to the actual mouse/Mary objective after transition; pending interior exit continues to James/Hans; forest return uses the existing return transition. No teleport to objective, remote acceptance, invented new rewards, changed original assets, combat rules or BODY/motion changes.

Verification: QuestJournalTest nine native tests cover all rows/available filter, locked prerequisites and last row/no rewards or movement, real first-touch NPC arrival/acceptance, actual defeat ledger/growth reward idempotency/forest completion/restart, inn exit/next NPC acceptance, wide layout and drag shielding, plus manual destination cancellation of pending door continuation. Existing inn reward -> growth -> Hans input chain, HUD touch areas, persistence/combat/weapon/FX gates retained. Native screenshots under app/build/reports/device-review/v97-*.png. Exact build proof appended only after CI/artifact/hash verification. Physical phone and user visual review remain pending.
