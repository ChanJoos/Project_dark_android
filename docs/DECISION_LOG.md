# PROJECT DARK 결정 및 제안 기록

이 문서는 승인된 결정을 아이디어와 분리합니다. 각 확정 항목에는 근거를 남깁니다. 상세 규칙은 인용한 원본 문서가 권위 문서입니다.

## 확정된 프로젝트/개발 결정

| 결정 | 범위와 의미 | 근거 |
|---|---|---|
| 개발 판단은 설계 → 데이터/출처 → 런타임 → 플레이 가능한 장면 → APK → 기기 증거 → 수락을 구분한다. | 클래스 단위 구현이나 컴파일만으로 기능 완료를 선언하지 않는다. | `docs/PROJECT_DARK_DEVELOPMENT_CONSTITUTION.md` |
| 구현 사실, 빌드 검증, 기기 검증, 시각 수락은 각각 별도 상태로 보고한다. | 증거가 없는 단계는 미확정으로 유지한다. | `AGENTS.md`, `docs/PROJECT_DARK_DEVELOPMENT_CONSTITUTION.md` |
| 사용자 승인 외형/동작과 소유권 경계를 보존하고, 기존 모듈과 계약을 먼저 조사한다. | 관련 도메인의 계약/검증을 확인한 뒤 변경한다. | `AGENTS.md`, 관련 handoff |
| 원작 근거가 없는 사실은 `UNRESOLVED`로 두며, 조정/대체안은 그 상태를 명시한다. | 제안이나 임시 fixture를 원작 정사로 표기하지 않는다. | `AGENTS.md`, `docs/PROJECT_DARK_DEVELOPMENT_CONSTITUTION.md`, `master/MASTER_LAW.md` |
| 포테 몬스터 v0.4 묶음은 검토용이며 해당 커밋에서 APK에 적용하지 않았다. | 에셋 존재를 런타임 통합이나 시각 수락으로 해석하지 않는다. | `0506929`, `assets/pote/review/monster_concepts_v0.4/README.md` |
| 다음 작업은 최신 근거와 현재 사용자 지시에 맞춰 선택한다. 오래된 baton의 티켓을 자동으로 재개하지 않는다. | 충돌하는 과거 상태를 확정 사실로 전파하지 않는다. | 2026-09-28 기준 상태 감사; 사용자 인수인계 요청 |

## 아이디어·기획 목표 (승인/구현 여부 별도 확인)

다음은 프로젝트 기획 문서가 다루는 목표 또는 검토 항목입니다. 이 목록에 있다는 이유만으로 현재 구현·승인 완료를 뜻하지 않습니다.

- 원작 세계와 규칙을 근거 기반으로 모바일에서 구현하고, 설치·저장 복구·성능·원작 비교 검수를 통과한 빌드를 배포 후보로 삼는 방향.
- 밀레스 이동에서 NPC 대화, 전투, 보상, 성장, 저장, 프로세스 재시작 복원까지 이어지는 플레이 루프.
- 직업·성장·전투·퀘스트·UI·경제·온라인 기능을 단계적으로 구현하는 항목.

세부 제안의 상태와 원작 근거는 `master/PROJECT_DARK_V0.6_PLAN_KO.md` 및 관련 출처/SSOT 문서에서 항목별로 확인합니다. 이 문서는 목표를 현재 기능으로 변환하지 않습니다.

## 이력

이 파일에는 새로 확정되거나 변경된 결정만 날짜와 근거를 붙여 추가합니다. 구현 진행률은 `docs/PROJECT_STATE.md`, 작업별 실행계획은 `docs/DIRECTOR_BACKLOG.md`에서 관리합니다.
