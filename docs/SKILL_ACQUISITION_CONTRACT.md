# Skill acquisition, slots and cooldown contract — v59

User selected **스크린샷 조건 적용**: capture stats and prerequisite proficiency are gameplay conditions for this project. This supersedes the earlier reference-only capture rule; it does not certify current original-server rules.

- Producer: `SkillBook` keeps the read-only 219-row Master projection. `acquisition_captures.json` adds twelve source-hashed martial-artist condition rows; `SkillAcquisition` reads these or the preserved capture legacy conditions. No original Master facts are overwritten.
- Consumer: skill-window **습득** calls `SkillAcquisition.learn`, checking current job, captured STR/INT/WIS/CON/DEX and all explicitly resolved prerequisites. No automatic grants. Missing conditions, ambiguous prerequisite levels, advancement routes and unresolved circle-5 material/event conditions fail closed with a visible reason. No inferred level-to-circle conversion or invented material/gold deduction.
- Slots: a learned ID may be assigned to any of eight slots, including utility skills whose field implementation is pending. Same-skill registration clears the chosen slot. Registering does not execute the skill. Slot selection inside the book selects its detail; field HUD taps execute. Checkpoints restore both learning and slots transactionally.
- Combat: `SkillRuntimeCatalog` defines 29 explicit B/ADAPTED single-target physical/magic and self-heal actions under real IDs. Numeric damage, MP, range and cooldown values are mobile playtest values, shown as 시험값. Elemental server formulas, group/AOE, stealth, utility, event spells and advanced effects are not claimed implemented. Unsupported entries show **전투 효과 준비 중** and cannot consume MP or fake a hit.
- All supported actions use `RuntimeCombatSession` → shared `CombatResolver` → runtime port. Learning gate, resource commit, shared action-ID cooldown and hit-frame application remain owned by the combat modules. Duplicate slots share the same timer. MP is deducted once on accepted input; rejected repeat/insufficient-resource/range input does not charge. Self heal targets the player without requiring a selected monster and caps at max HP.
- A resolved player action advances proficiency once by one point up to 100 (ADAPTED training progression). No proficiency is awarded for rejected input. Original skill-failure probabilities remain unresolved.
- Descriptions do not cycle on body taps. Effect/condition tabs are explicit; longer text uses labelled up/down buttons with bounded scrolling. The total cooldown is shown in detail and remaining cooldown overlays field slots.

This change does not mislabel that fixture as a reachable device profession path. Original utility effects, all 219 effects, original combat balance, circle/material rules and physical-device QA are pending. Cooldowns remain session timers; a persisted offline cooldown policy is not yet defined.
