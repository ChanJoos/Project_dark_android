## 1. 어둠의전설 모바일 기획안

기획 개정 0.6 | 2026년 9월 9일 | Android 네이티브 프로젝트

원작의 세계와 직업, 전투 규칙, 메뉴 구조를 모바일에서 재현한다. 개발의 판단 기준은 공식 가이드에 대한 규칙 일치, 기준 화면에 대한 시각 일치, 실제 입력과 반응에 대한 동작 일치다. 세 기준을 각각 검수해야 “동일하게 구현했다”고 판정할 수 있다.

현재 실행 소스는 0.5 시제품이다. 이 문서는 이후 구현을 위한 명세이며, 문서 개정 번호가 게임 기능의 구현 완료를 뜻하지 않는다. 원작 마을과 정식 스킬 데이터로 한 구간을 완성한 다음 콘텐츠를 확장한다.

| 판단 항목 | 개발 기준 |
|---|---|
| 기준 버전 | 공식 가이드의 2025년 2월 20일 표기를 기준점으로 보관한다. 이후 업데이트는 기능별 차이표를 만든 뒤 반영한다. |
| 원작을 유지할 부분 | 고유명사·직업 역할·습득 조건·재화 의미·퀘스트 분류·UI 정보 구조와 픽셀 아트의 비례를 유지한다. |
| 모바일에서 조정할 부분 | 키보드와 마우스 입력을 터치로 대응하고 글자·터치 영역·안전 영역을 조정한다. 이 변경은 모바일 설계로 명시한다. |
| 싱글플레이 범위 | 현재 프로젝트는 로컬 플레이다. 온라인 파티·거래·길드·랭킹까지 같은 경험을 제공하려면 별도 서버 단계가 필요하다. |
| 출시 판단 | 설치·저장 복구·성능·원작 비교 검수를 모두 통과한 빌드만 배포 후보로 둔다. |

검토 순서: 원작 차이, 스토리와 성장, 전투와 움직임, UI와 경제, 콘텐츠와 온라인 기능, 제작 자산, 기술 구조, 검수와 실행 일정. 각 표의 “요구”는 구현해야 할 내용이며 현재 완성된 기능을 의미하지 않는다.

## 2. 원작 기준과 우선 수정 사항

근거가 확인된 규칙부터 시제품의 임시 설계를 교체한다.

| 항목 | 공식 기준과 필요한 변경 |
|---|---|
| 생성 S02 | 한글 이름 6자, 영문 12자. 성별·헤어·색상 선택을 제공한다. 현재 일괄 12자와 외형 2종은 교체 대상이다. 혼합 문자 판정은 별도 확인한다. |
| 기술 S08 | 기술은 MP를 쓰지 않고 마법은 MP를 쓴다. 현재 모든 직업 기술의 MP 8 소모를 공통 규칙으로 사용하면 안 된다. |
| 성장 S09 S10 | STR·CON·INT·DEX·WIS와 레벨 상승 포인트를 분리한다. 기본 능력치와 장비 보정을 합산하되 UI에서 구분한다. |
| 사망 S07 | 유령 상태와 부활 장소·조건을 구현한다. 현 시제품의 Gold 10% 손실 후 야영지 복귀는 원작 규칙이 아니다. |
| 통합슬롯 S04 | 7개 탭과 등록·이동·교환·해제를 구현한다. “7개 탭”을 “7칸”으로 해석하지 않는다. |
| 퀘스트 S05 | 분류·진행 필터·추적·포기·최대 15개 수락을 지원한다. 단일 사냥 과제만으로 전체 퀘스트를 대체하지 않는다. |
| 강화 S05 | 에테르 강화 실패는 장비 파괴나 단계 하락으로 처리하지 않는다. 주문서 강화와 별도 규칙으로 둔다. |
| 정보 S09 | AC는 낮을수록 방어가 유리한 지표다. 숫자가 커지면 항상 좋다는 공통 비교 색상을 적용하지 않는다. |

규칙 표기는 네 종류다. “공식”은 해당 문서에 직접 확인한 사실, “관찰”은 실제 플레이 프레임으로 확인한 사실, “설계”는 모바일 구현 판단, “확인 필요”는 아직 값이나 행동을 결정할 근거가 없는 항목이다. 출처는 문서 끝의 식별자로 연결한다.

홈페이지의 이용자 게시글·팬게임·2004년 별도 모바일 SRPG 자료는 현 PC 원작의 정사나 전투 규칙을 확정하는 근거로 쓰지 않는다. 오래된 플레이 영상은 촬영 당시 버전에 한해 참고한다.

## 3. 세계관과 스토리 진행

공식 세계의 이름과 사건 순서를 유지하고 퀘스트를 데이터로 연결한다.

마이소시아를 세계의 기준 명칭으로 사용한다[S01]. 빛의신전과 솜누스의중심은 부활 시스템에 연결되는 장소다[S07]. 메인 스토리의 사건 순서, 인물 관계, 마을별 대사에는 퀘스트 원문과 버전 근거를 붙인다. 시제품의 야영지·수련 동굴·안내인은 검증용 콘텐츠로 분리한다.

세계 자료집은 지역 ID, 공식 표기, 연결 지역, 시대·사건, 관련 NPC, 자료 출처를 기록하며 실제 이동 경로와 지도 연결 그래프가 일치해야 한다. 서사는 원작의 시작 조건·NPC 대화·수행 조건·완료 대화·보상 순서를 보존하고 분기 조건을 직업·레벨·선행 퀘스트·아이템으로 표현한다. 대화 화면은 화자와 대사, 선택지, 다음·닫기를 제공하며 반복 터치로 보상/퀘스트가 중복되지 않아야 한다. 퀘스트 상태는 미발견, 수락 가능, 진행 중, 완료 가능, 보상 수령, 포기를 분리하고 처치·수집·방문·대화를 조합한다. 포기 초기화 대상/예외를 퀘스트마다 저장하고 재개 후 선택 분기와 보상 여부를 유지한다. 원작의 대화 중심 전달과 장면 전환을 우선하며 새 영상·자동 스킵·현대식 길 안내 추가는 변경 사유를 명세한다.

첫 구현 구간은 실제 시작 지역 한 곳, 해당 지역 NPC, 원작 초반 퀘스트 한 줄기, 연결된 사냥터로 제한한다. 지역 이름과 대사를 확정하기 전에는 제작용 ID만 사용하고 임의의 신화·인물 관계를 원작 사실처럼 채우지 않는다. 선행 조건을 만족하지 않으면 시작할 수 없고 모든 분기가 막힘 없이 종료되며 완료 대사와 보상을 다시 받을 수 없어야 한다. 대화 종료·앱 중단·재접속에서 동일 진행 상태를 복원한다.

## 4. 캐릭터와 직업 성장

직업별 역할 차이와 성장 단계의 의미를 데이터 구조에서 보존한다.

- 전사: 높은 체력과 강한 공격. 체력을 소비하는 필살기의 조건/위험을 개별 기술 데이터로 표현.
- 도적: 은신·치명 공격·몬스터 속성 파악·연막을 구분. 은신 해제/탐지를 단순 피해 배율과 분리.
- 마법사: 다수 대상 공격과 마력 운용. 낮은 생존력/동료 지원 역할을 전사형 근접 공격으로 대체하지 않음.
- 성직자: 회복·보호·해제·아군 강화의 대상/효과를 구분.
- 무도가: 맨손·발차기·도약·마비의 개별 행동. 도약 중 충돌과 착지 실패 별도 검수.

일반 레벨 1~99, 승급과 2차·3차 직업 단계, 어빌리티 경험치를 서로 다른 필드로 관리한다[S10]. 통합 표시 레벨을 내부 성장 상태 하나로 사용하지 않는다. 일반 레벨 상승 시 능력치 포인트 2점을 지급하고 중복 지급을 방지한다. STR·CON·INT·DEX·WIS의 역할을 보존한다[S09]. 1~99 성장 중 CON/WIS의 HP·MP 증가 영향 공식은 확인 전 확정하지 않는다. 기술 습득은 레벨·능력치·선행 기술·아이템·Gold 조건을 검사한다[S08]. 공통 기술, 직업 서클, 승급 이후 기술을 분리하며 숙련도 실패 가능성을 처리한다. 시제품 Lv10 전직/자동 기술 획득은 유지 여부 확인 대상이다.

## 5. 전투 규칙과 판정

기술 효과, 애니메이션, 입력을 분리하되 같은 행동 식별자로 연결한다. 행동 요청은 생존 여부→제어 불가 상태→대상 유형→거리→시야→자원→습득 조건→재사용 시간을 검사한다. 승인되면 자원/재사용을 한 번 반영하고 지정 발동 이벤트에서 피해·회복·상태를 적용한다. 정확한 원작 발동 시점은 별도 계측한다.

기본 공격은 대상·방향·사거리·무기·공격 주기를 갖고 대상 소멸/사거리 이탈 처리 정책을 명시한다. 기술/마법은 kind, 자원, 준비, 발동 시점, 후딜, 재사용, 대상 필터, 숙련 조건을 갖고 기술 MP 소모는 0[S08]. AC/HIT/DAM을 별도 필드로 두고 미확정 확률·방어·속성 공식을 정식 값으로 승격하지 않는다. 상태 이상은 효과 ID, 지속, 중첩, 면역, 해제, 저장 정책을 가지며 마비·은신·저주·보호 허용 행동을 각각 정의한다. 대상은 자신·아군·적·지면을 구분하고 범위 판정 타일/이펙트를 함께 검수한다. 사망 이벤트는 한 번만 처리하고 유령 전환, 부활 장소, 대가, 이아의구원을 분리한다[S07].

도적의 속성 파악을 보존한다[S01]. 시제품 목걸이·벨트 무료 속성 순환 버튼과 1.3배 상성표는 테스트 설정이다. 정식 장비/속성 대응, 비용, 상성 배율은 자료 확보 후 확정한다.

## 6. 이동과 행동 상태

좌표 변경만으로 걷기를 대신하지 않는다. 시제품의 165ms 이동 허용값은 임시다. 표시 좌표와 논리 좌표를 분리하고 출발점·도착점·시작 시간·지속 시간으로 보간한다. 카메라/장비도 같은 표시 좌표를 사용한다.

대기는 이동·공격·대화 요청과 방향 전환을 구분한다. 걷기는 다음 타일 충돌을 검사하고 구간을 예약한 뒤 도착 시 좌표를 확정한다. 공격/시전은 준비·발동·회복을 나누고 이동 취소/대상 변경 가능 시점을 데이터화한다. 피격 표현과 행동 중단을 구분한다. 사망 시 예약 행동/경로를 정리하고 유령 상태로 전환한다. 지역 전환 시 좌표·카메라·대상을 초기화하고 앱 중단 시 타이머 폭주를 막는다.

터치 바닥 이동과 방향 입력은 동일 명령으로 연결한다. UI 손가락은 월드 이동을 발생시키지 않는다. 멀티터치, 화면 밖 드래그, ACTION_CANCEL, 팝업을 검사한다. 길찾기는 도달 불가, 움직이는 장애물, 목적지 점유, 출입구, 긴 경로를 처리한다. 원작 방향 수·대각선·한 칸 시간·연속 보행 프레임은 계측 후 결정한다.

## 7. 동작 영상과 애니메이션 명세

V01/V02는 페이지 확인만 되었고 재생 실패했으므로 실제 프레임 수·보행 속도·공격 타이밍을 확정하지 않는다. 모션은 대기·방향 전환·걷기·무기 공격·맨손 공격·마법·피격·사망·유령·부활·상호작용·도약과 직업별 특수 행동을 목록화한다. 클립 ID, 캐릭터·장비, 방향, 프레임 영역/시간, 반복, 발 기준점, 손·무기 결합점, 효과 발동 이벤트를 저장한다. 관찰 URL/버전/시각/FPS/가림/신뢰도를 기록한다. 한 행동 최소 3회 관찰 후 발 접지·위치 변화·효과·다음 행동을 프레임 표시한다. 누락 durationMs/frameCount/directionCount는 null로 둔다.

스프라이트는 투명 원본이 필요하다. 캡처 단일 그림은 실제 재생 자산과 구분한다. 30/60fps에서 행동 시간/결과가 같고 공격 효과 중복이 없으며 장비/그림자가 기준점을 벗어나지 않아야 한다.

## 8. 기본 화면과 모바일 조작

공식 게임 가이드 화면의 정보 구조를 따른다. HP·MP·경험치, 미니맵, 통합슬롯, 지역 지도, 그룹 표시를 유지한다[S03]. 상태 표시는 HP·MP·일반 EXP·어빌리티 EXP를 구분한다. 미니맵/지역지도는 축소·확대·접기, NPC/건물 hover 정보는 탭 상세로 변환한다. 월드 지도는 별도 화면이며 무료 순간이동으로 대체하지 않는다. 통합슬롯 7개 탭[S04]을 유지하고 길게 누르기 편집/드래그 등록·교환/해제를 제공한다. 가로 화면, 이동/행동 손가락 영역 분리, 48dp 이상 터치 목표는 모바일 설계다. 팝업은 최상위부터 닫고 아래 월드 터치를 차단한다.

가독성은 픽셀 크기/화면 배율/글자 배율을 분리한다. 긴 한글 이름·수량·설명은 줄바꿈/상세창을 사용한다. 왼손/오른손, 컷아웃, 시스템 제스처, 화면비, 태블릿, 키보드, 큰 글자, 진동/효과/색 이외 상태 표현을 검수한다.

## 9. 메뉴와 화면별 흐름

우측 메뉴[S05]: 설정·인벤토리·정보·스킬·퀘스트·제조·강화·보스·퀵던전·캐시샵·이벤트. 미구현 기능 활성 버튼 금지. 인벤토리는 필터, 사용량/최대칸, 상세·사용·장착·해제·이동, 잠금/기간/수량 상태를 표현한다. 캐릭터 정보는 장비, 이름·직업·레벨, 소속, 칭호·상징, 소개, 기본·추가·상세 능력치, 기록을 구분한다. 스킬은 공통·직업 서클·승급 목록과 잠금 사유/비용/효과/대상/재사용/숙련/슬롯을 연결한다. 퀘스트는 메인·일반·직업·이벤트, 진행 필터, 추적, 최대15, 포기 예외를 표현한다. 상단 메뉴[S06]는 접속자·친구·길드·게시판·편지이며 오프라인에서 가짜 서버 응답을 만들지 않는다.

## 10. 아이템과 경제 및 제작

아이템 정의와 소유 인스턴스를 분리한다. 정의: 종류·장비부위·효과·중첩·사용 조건·판매 정책·이미지. 인스턴스: 고유 ID·수량·강화·기간·잠금. Gold/라르 등 재화를 별도 장부로 관리하고 원인/전후 잔액을 기록한다. 상점은 가격/수량/공간을 사전 검사하고 원자 저장한다. 전리품은 드롭 테이블·소유권·수거 거리·소멸·가방 가득 참·바닥 중첩을 정의한다. 제조는 분류·레시피 해금·재료·Gold·성공/실패를 데이터화한다[S05]. 에테르 강화 실패 보존 및 같은 부위 이전 조건, 주문서 강화 별도 규칙을 둔다[S05]. 기간 가방 만료 시 임의 자동 소실 금지. 유료/거래소/확률형은 로컬 가상 버튼으로 구현하지 않는다.

## 11. 월드와 몬스터 및 던전

필드/마을은 타일 크기·충돌·높이·가림·출입구·NPC·안전구역·BGM·지도라벨을 정의한다. 지역 연결은 출발맵·조건·도착맵·좌표·시선·비용을 하나의 규칙으로 둔다. 몬스터는 종류·속성·HP·능력치·감지·추적·공격·기술·복귀·드롭·EXP·출현조건을 데이터 관리한다. AI는 대기·배회·발견·추적·공격·귀환·사망으로 분리한다. 던전/보스는 입장·목표·실패·재입장·초기화·보상을 정의한다. 퀵던전은 유리드에어리어와 모집·참가 흐름을 연결한다[S05].

## 12. 온라인 기능과 운영 범위

현재는 로컬 모험. 서버 후속 요구로 인증/서버선택/캐릭터 슬롯·복구, 파티/협동, 친구 최대20명/길드[S06], 채팅/게시판, 편지/거래, PvP/길드전/랭킹/시즌/이벤트를 보존한다. 편지에 아이템·Gold를 보내지 않는 규칙을 보존한다[S06]. 최소 서버 구조는 인증, 캐릭터 저장, 월드 처리, 인벤토리 원장, 채팅, 운영 도구이며 거래/보상은 요청 ID로 중복 방지하고 클라이언트 잔액/피해를 신뢰하지 않는다.

## 13. 그래픽과 사운드 제작

캐릭터는 성별·헤어·색상·직업·장비·방향별 클립, 가림 순서를 검수한다. 타일/오브젝트는 바닥·벽·건물·식생·문·출입효과를 분리한다. UI는 테두리·배경·아이콘·선택·비활성·누름·폰트를 목록화한다. 전투 효과는 시전·투사체·명중·회복·상태·사망·부활 이벤트에 연결한다. 사운드는 지역 BGM, 발, 무기, 피격, 주문, 창, 아이템, 퀘스트, 사망을 목록화한다. 접근성은 BGM/SFX 분리, 음소거, 진동, 효과 감소, 색/소리 단독 필수정보 금지.

자산 등록은 ID, 출처, 기준 버전, 해시, 원본 크기, 색/알파, 프레임, 배율, 기준점, 사용 화면, 제작 상태를 갖는다. 원본/수정본을 분리한다. 픽셀아트는 정수 배율 우선, 픽셀 정렬/발 접점 통일. 미청취 사운드 길이/주문음을 확정하지 않는다.

## 14. 개발 구조와 성능 목표

GameState·GameRenderer·GameView 분리를 유지하되 World, Combat, Quest, Inventory, Progression, Animation, Audio, Save 서비스를 단계적으로 분리한다. 읽기 상태/명령 큐를 사용하고 Android 생명주기/시뮬레이션 시간 소유자를 통일한다.

데이터는 고유 ID/스키마 버전과 누락참조·중복ID·음수비용·순환퀘스트 빌드 검사를 갖는다. 저장은 캐릭터·성장·장비·퀘스트·재화·HUD를 원자 저장하고 복구/마이그레이션/보상 이력을 포함한다. 단조 시간/명시 난수, 앱 복귀 폭주 방지. 초기 성능 제안은 저사양30fps/상위60fps/30분 전투 지속 메모리 증가 없음. 화면밖 culling/자산재사용/프레임 객체축소/이펙트 제한. 디버그·검수·배포 분리와 버전·자산해시·세이브버전/롤백 묶음을 보관한다.

성능은 콜드스타트, 지역 이동, 다수 몬스터, 광역마법, 인벤토리 반복, 저장, 백그라운드 복귀를 측정한다. Android 빌드/실기기 실행은 문서 작성 시점에는 검증되지 않았다.

## 15. 검수와 개발 실행 순서

기능 수보다 원작 일치와 끝까지 플레이 가능한 구간을 우선한다. 첫 단계는 기준 버전, 첫 지역, 퀘스트 원문, 정식 아이템·기술 목록, 움직임 영상 구간을 확정하며 근거 없는 필수 값을 배포 데이터에 남기지 않는다. 이후 데이터/규칙, 플레이 가능한 세로 구간, 모바일 UI, 자산/애니메이션, 저장/복구, 성능/실기기, 원작 비교 검수 순으로 통합한다. 각 단계는 정상 경로뿐 아니라 실패/취소/재접속/중복 입력을 검수한다.
