어둠의전설 모바일 기획안
기획 개정 0.6 | 2026년 9월 9일 | Android 네이티브 프로젝트
원작의 세계와 직업, 전투 규칙, 메뉴 구조를 모바일에서 재현한다. 개발의 판단 기준은 공식 가이드에 대한 규칙 일치, 기준 화면에 대한 시각 일치, 실제 입력과 반응에 대한 동작 일치다. 세 기준을 각각 검수해야 “동일하게 구현했다”고 판정할 수 있다.
현재 실행 소스는 0.5 시제품이다. 이 문서는 이후 구현을 위한 명세이며, 문서 개정 번호가 게임 기능의 구현 완료를 뜻하지 않는다. 원작 마을과 정식 스킬 데이터로 한 구간을 완성한 다음 콘텐츠를 확장한다.
판단 항목
개발 기준
기준 버전
공식 가이드의 2025년 2월 20일 표기를 기준점으로 보관한다. 이후 업데이트는 기능별 차이표를 만든 뒤 반영한다.
원작을 유지할 부분
고유명사·직업 역할·습득 조건·재화 의미·퀘스트 분류·UI 정보 구조와 픽셀 아트의 비례를 유지한다.
모바일에서 조정할 부분
키보드와 마우스 입력을 터치로 대응하고 글자·터치 영역·안전 영역을 조정한다. 이 변경은 모바일 설계로 명시한다.
싱글플레이 범위
현재 프로젝트는 로컬 플레이다. 온라인 파티·거래·길드·랭킹까지 같은 경험을 제공하려면 별도 서버 단계가 필요하다.
출시 판단
설치·저장 복구·성능·원작 비교 검수를 모두 통과한 빌드만 배포 후보로 둔다.

검토 순서: 원작 차이, 스토리와 성장, 전투와 움직임, UI와 경제, 콘텐츠와 온라인 기능, 제작 자산, 기술 구조, 검수와 실행 일정. 각 표의 “요구”는 구현해야 할 내용이며 현재 완성된 기능을 의미하지 않는다.

원작 기준과 우선 수정 사항
근거가 확인된 규칙부터 시제품의 임시 설계를 교체한다.
항목
공식 기준과 필요한 변경
생성 S02
한글 이름 6자, 영문 12자. 성별·헤어·색상 선택을 제공한다. 현재 일괄 12자와 외형 2종은 교체 대상이다. 혼합 문자 판정은 별도 확인한다.
기술 S08
기술은 MP를 쓰지 않고 마법은 MP를 쓴다. 현재 모든 직업 기술의 MP 8 소모를 공통 규칙으로 사용하면 안 된다.
성장 S09 S10
STR·CON·INT·DEX·WIS와 레벨 상승 포인트를 분리한다. 기본 능력치와 장비 보정을 합산하되 UI에서 구분한다.
사망 S07
유령 상태와 부활 장소·조건을 구현한다. 현 시제품의 Gold 10% 손실 후 야영지 복귀는 원작 규칙이 아니다.
통합슬롯 S04
7개 탭과 등록·이동·교환·해제를 구현한다. “7개 탭”을 “7칸”으로 해석하지 않는다.
퀘스트 S05
분류·진행 필터·추적·포기·최대 15개 수락을 지원한다. 단일 사냥 과제만으로 전체 퀘스트를 대체하지 않는다.
강화 S05
에테르 강화 실패는 장비 파괴나 단계 하락으로 처리하지 않는다. 주문서 강화와 별도 규칙으로 둔다.
정보 S09
AC는 낮을수록 방어가 유리한 지표다. 숫자가 커지면 항상 좋다는 공통 비교 색상을 적용하지 않는다.

규칙 표기는 네 종류다. “공식”은 해당 문서에 직접 확인한 사실, “관찰”은 실제 플레이 프레임으로 확인한 사실, “설계”는 모바일 구현 판단, “확인 필요”는 아직 값이나 행동을 결정할 근거가 없는 항목이다. 출처는 문서 끝의 식별자로 연결한다.
홈페이지의 이용자 게시글·팬게임·2004년 별도 모바일 SRPG 자료는 현 PC 원작의 정사나 전투 규칙을 확정하는 근거로 쓰지 않는다. 오래된 플레이 영상은 촬영 당시 버전에 한해 참고한다.

세계관과 스토리 진행
공식 세계의 이름과 사건 순서를 유지하고 퀘스트를 데이터로 연결한다.
마이소시아를 세계의 기준 명칭으로 사용한다[S01]. 빛의신전과 솜누스의중심은 부활 시스템에 연결되는 장소다[S07]. 메인 스토리의 사건 순서, 인물 관계, 마을별 대사에는 퀘스트 원문과 버전 근거를 붙인다. 시제품의 야영지·수련 동굴·안내인은 검증용 콘텐츠로 분리한다.
설계 요소
요구와 검수 방법
세계 자료집
지역 ID, 공식 표기, 연결 지역, 시대·사건, 관련 NPC, 자료 출처를 기록한다. 실제 이동 경로와 지도 연결 그래프가 일치해야 한다.
서사 구조
원작의 시작 조건·NPC 대화·수행 조건·완료 대화·보상 순서를 보존한다. 분기 조건은 직업·레벨·선행 퀘스트·아이템으로 표현한다.
대화 화면
화자와 대사, 선택지, 다음·닫기 버튼을 제공한다. 선택지 반복 터치로 보상이나 퀘스트가 중복 발생하지 않아야 한다.
퀘스트 상태
미발견, 수락 가능, 진행 중, 완료 가능, 보상 수령, 포기를 분리한다. 처치·수집·방문·대화 조건을 조합한다.
포기와 재개
포기 시 초기화 대상과 예외를 퀘스트마다 저장한다[S05]. 저장 후 재개해도 선택 분기와 보상 수령 여부를 유지한다.
연출
원작의 대화 중심 전달과 장면 전환을 우선한다. 새 영상 연출·자동 스킵·현대식 길 안내를 추가하면 변경 사유를 명세한다.

첫 구현 구간은 실제 시작 지역 한 곳, 해당 지역 NPC, 원작 초반 퀘스트 한 줄기, 연결된 사냥터로 제한한다. 지역 이름과 대사를 확정하기 전에는 제작용 ID만 사용하고 임의의 신화·인물 관계를 원작 사실처럼 채우지 않는다.
스토리 수락 기준: 선행 조건을 만족하지 않으면 시작할 수 없고, 모든 분기에서 막힘 없이 종료되며, 완료 대사와 보상을 다시 받을 수 없어야 한다. 대화 종료·앱 중단·재접속의 세 시점에서 동일한 진행 상태를 복원한다.

캐릭터와 직업 성장
직업별 역할 차이와 성장 단계의 의미를 데이터 구조에서 보존한다.
직업 S01
구현해야 하는 역할
전사
높은 체력과 강한 공격을 중심에 둔다. 체력을 소비하는 필살기의 조건과 위험을 개별 기술 데이터로 표현한다.
도적
은신·치명 공격·몬스터 속성 파악·연막을 구분한다. 은신 해제 조건과 탐지 조건을 단순 피해 배율과 분리한다.
마법사
다수 대상 공격과 마력 운용을 설계한다. 낮은 생존력과 동료 지원이라는 역할을 전사와 같은 근접 공격으로 대체하지 않는다.
성직자
회복·보호·해제·아군 강화의 대상과 효과를 구분한다. 자신에게만 쓰는 회복은 전체 직업 재현으로 판정하지 않는다.
무도가
맨손·발차기·도약·마비의 개별 행동을 둔다. 도약 중 충돌과 착지 실패 조건을 별도로 검수한다.

일반 레벨 1~99, 승급과 2차·3차 직업 단계, 어빌리티 경험치를 서로 다른 필드로 관리한다[S10]. 통합 표시 레벨을 내부 성장 상태 하나로 사용하지 않는다. 일반 레벨 상승 시 능력치 포인트 2점을 지급하고 중복 지급을 방지한다.
STR·CON·INT·DEX·WIS의 역할을 보존한다[S09]. 특히 1~99 성장 중 CON과 WIS가 HP·MP 증가에 영향을 주므로 장비 포함 수치와 육성 이력을 어떻게 적용하는지 공식을 확인해야 한다. 공식 수치표가 확보되기 전 자동 성장식을 확정하지 않는다.
기술 습득은 레벨·능력치·선행 기술·아이템·Gold 조건을 검사한다[S08]. 공통 기술, 직업 서클, 승급 이후 기술을 분리하며 숙련도에 따른 실패 가능성을 처리한다. 시제품의 Lv.10 전직 및 자동 기술 획득은 유지 여부 확인 대상이다.
검수: 생성 입력 경계, 포인트 미사용·사용·재분배, 전직 전후 저장, 조건 미달 습득 차단, 장비 교체 시 기본 능력치 불변, 어빌리티 경험치와 일반 경험치의 독립성을 확인한다.

전투 규칙과 판정
기술 효과, 애니메이션, 입력을 분리하되 같은 행동 식별자로 연결한다.
행동 요청은 생존 여부, 제어 불가 상태, 대상 유형, 거리, 시야, 자원, 습득 조건, 재사용 시간을 순서대로 검사한다. 실행이 승인되면 자원과 재사용 시간을 한 번 반영하고, 지정한 발동 이벤트에서 피해·회복·상태 효과를 적용한다. 이것은 구현 설계이며 원작의 정확한 발동 시점은 별도 계측한다.
전투 요소
필요 데이터와 실패 처리
기본 공격
공격 가능한 대상·방향·사거리·무기·공격 주기. 대상 소멸이나 사거리 이탈 시 행동 취소 또는 빗나감 처리를 명시한다.
기술과 마법
kind, 소모 자원, 발동 준비, 발동 시점, 후딜, 재사용, 대상 필터, 숙련 조건. 기술의 MP 소모는 0으로 관리한다[S08].
명중과 피해
AC·HIT·DAM 등 상세 능력치를 별도 필드로 둔다[S09]. 공식 확률·방어·속성 공식이 확보되기 전 시제품 배율을 정식 값으로 승격하지 않는다.
상태 이상
효과 ID, 지속 시간, 중첩 방식, 면역, 해제 유형, 저장 정책. 마비·은신·저주·보호는 허용 행동을 각각 정의한다.
대상과 범위
자신·아군·적·지면을 구분한다. 범위 판정은 타일 기준과 화면 이펙트 범위를 함께 검수한다.
사망과 부활
사망 이벤트는 한 번만 처리한다. 유령 전환, 부활 장소, 대가, 이아의구원 처리를 분리한다[S07]. 정확한 페널티 수치는 확인 후 입력한다.

원작의 속성 파악은 도적 역할에 포함된다[S01]. 시제품의 목걸이·벨트 무료 속성 순환 버튼과 1.3배 상성표는 테스트 설정으로 둔다. 장비와 속성의 정식 대응, 전환 비용, 상성 배율은 자료를 확보한 뒤 확정한다.
검수: 같은 actionId의 피해 중복 금지, MP 부족 시 무차감, 무효 대상에 보상 미지급, 적·플레이어 동시 사망 순서, 숙련 실패, 쿨다운 중 연타, 마비 중 이동·공격 요청 차단을 확인한다.

이동과 행동 상태
좌표 변경만으로 걷기를 대신하지 않고 이동 시작부터 정지까지 설계한다.
현재 소스는 타일 좌표를 즉시 바꾸며 165ms 간격으로 다음 이동을 허용한다. 이 숫자는 시제품 값이다. 표시 좌표를 논리 좌표와 분리하고, 출발점·도착점·시작 시간·지속 시간으로 화면 위치를 보간한다. 카메라와 장비도 같은 표시 좌표를 사용해야 타일이 순간적으로 튀지 않는다.
상태 또는 상황
전이와 처리 요구
대기와 방향 전환
이동·공격·대화 요청을 받는다. 바라보는 방향만 바뀌는 상황을 위치 이동과 구분한다.
걷기
다음 타일 충돌을 검사하고 이동 구간을 예약한다. 도착 시 좌표를 확정한다. 이동 중 새 목표 입력과 정지 정책은 원작 영상으로 확인한다.
공격과 시전
준비·발동·회복 구간을 나눈다. 발동 전후의 이동 취소·대상 변경 가능 시점을 기술별 데이터로 둔다.
피격과 제어 불가
피격 표현만 발생하는 경우와 행동이 끊기는 경우를 구분한다. 모든 피격이 강제 경직이라는 가정을 넣지 않는다.
사망과 유령
사망 시 예약 행동과 경로를 정리하고 부활 상태로 전환한다. 유령의 이동·상호작용 허용 범위는 독립 규칙으로 둔다.
전환과 앱 중단
지역 전환에서 좌표·카메라·대상을 함께 초기화한다. 싱글플레이는 중단 시 타이머를 멈추고 복귀 후 큰 시간 차를 한 번에 누적하지 않는다.

터치 바닥 이동과 방향 입력은 동일한 이동 명령으로 연결한다. UI를 누른 손가락은 월드 이동을 발생시키지 않는다. 두 손가락 이동·공격 중 한쪽만 떼기, 화면 밖 드래그, ACTION_CANCEL, 팝업 열기를 각각 검사한다.
길찾기는 도달 불가, 움직이는 장애물, 목적지 점유, 출입구, 긴 경로를 처리한다. 원작의 이동 방향 수·대각선 허용·한 칸 시간·연속 보행 프레임은 계측 후 결정한다. 경로 탐색 방식 자체가 원작과 같다는 주장은 하지 않는다.

동작 영상과 애니메이션 명세
모션의 수치와 원본 프레임이 확보되어야 전체 움직임 재현이 완료된다.
영상 확인 기록: V01과 V02의 제목·채널·페이지를 확인했으나 두 영상 모두 플레이어가 검은 화면에서 로딩 상태로 멈췄다. currentTime은 0, readyState는 0이었다. 따라서 이번 판본에는 실제 장면을 보고 측정한 프레임 수·보행 속도·공격 타이밍이 없다. 페이지 열람을 영상 관찰 완료로 처리하지 않는다.
제작 단위
필수 명세
모션 세트
대기·방향 전환·걷기·무기 공격·맨손 공격·마법·피격·사망·유령·부활·상호작용·도약을 목록화한다. 직업별 특수 행동은 추가한다.
클립 자료
클립 ID, 캐릭터·장비, 방향, 프레임 영역, 프레임별 시간, 반복, 발 기준점, 손·무기 결합점, 효과 발동 이벤트를 저장한다.
관찰 기록
영상 URL, 게시·촬영 버전, 관찰 시작·종료 시각, 재생 배속, 영상 FPS, 관찰된 행동, 가림·편집 여부, 신뢰도를 기록한다.
계측 절차
한 행동을 최소 3회 연속 관찰한다. 발 접지·위치 변화·효과 발생·다음 행동 시작을 프레임으로 표시한다. 영상의 중복 프레임은 게임 프레임과 구분한다.
시각 검수
원작과 같은 방향·장비·배경에서 기준점, 프레임 순서, 이동 궤적, 발동 순간을 나란히 비교한다. 확대 보간으로 픽셀이 흐려지는지도 확인한다.
누락 처리
아직 없는 durationMs·frameCount·directionCount는 null로 저장한다. 누락 클립을 정식 배포 자산으로 승인하지 않는다.

스프라이트는 배경이 없는 투명 원본이 필요하다. 현재 캡처에서 자른 단일 그림으로는 팔다리 움직임, 방향별 뒷모습, 장비 겹침을 재현할 수 없다. 기존 캡처는 화면 비교용으로 보관하고 실제 재생 자산과 구분한다.
동작 검수 목표는 30fps와 60fps에서 행동 시간과 결과가 같고, 공격 효과가 클립 재생 횟수만큼 중복 발생하지 않으며, 장비와 그림자가 캐릭터 기준점을 벗어나지 않는 것이다. 허용 시간 오차는 계측 영상의 한 프레임을 기준으로 정한다.

기본 화면과 모바일 조작
공식 게임 가이드의 화면을 기준으로 정보 구조와 조작 의미를 재현한다.
홈페이지의 웹 메뉴를 게임 HUD로 옮기는 것이 아니라 공식 가이드에 실린 게임 화면을 따른다. HP·MP·경험치, 미니맵, 통합슬롯, 지역 지도, 그룹 표시를 유지한다[S03]. 캡처의 픽셀 위치와 모바일 터치 영역은 서로 다른 설계 항목으로 관리한다.
화면 요소
모바일 대응과 수락 기준
상태 표시
HP·MP·일반 경험치·어빌리티 경험치를 구분한다. 수치·색상·막대가 같은 값을 표시하며 편집 후 위치와 방향을 복원한다.
미니맵과 지역 지도
축소·확대·접기를 제공한다. 지역 지도 T 키를 지도 버튼에 대응하고 NPC·건물의 마우스 올림 정보는 탭 상세로 바꾼다.
월드 지도
지역 지도와 별도 화면으로 둔다. 원작의 이동 수단·아이템 조건을 임의의 무료 순간이동 버튼으로 대체하지 않는다[S03].
통합슬롯
7개 탭을 유지한다[S04]. 길게 누르기 편집, 끌어 등록·교환, 등록 해제를 제공한다. 해제해도 아이템은 사라지지 않는다.
조작 배치
가로 화면을 기본 설계로 둔다. 이동과 행동의 손가락 영역을 분리하며 실제 터치 영역은 48dp 이상을 목표로 한다. 원작 규격이 아닌 모바일 목표다.
팝업과 뒤로가기
최상위 창부터 닫고 입력을 소비한다. 창 아래 월드로 터치가 통과하지 않아야 한다. 겹친 창의 활성 순서와 저장 정책을 정의한다.

가독성은 원본 픽셀 크기, 화면 배율, 글자 배율을 분리해 검수한다. 긴 한글 이름·수량·설명은 줄바꿈 또는 상세 창을 사용한다. 좁은 화면에서 글자를 무조건 줄여 끼워 넣지 않는다.
입력 검수는 왼손·오른손 설정, 컷아웃, 시스템 제스처, 16:9·긴 화면·태블릿, 키보드 표시, 큰 글자 설정을 포함한다. 진동·이펙트 강도와 색 이외의 상태 구분도 설정으로 제공한다.

메뉴와 화면별 흐름
현재 축약 메뉴를 공식 분류에 맞춰 확장하고 빈 화면까지 정의한다.
메뉴 묶음
화면 요구
우측 메뉴 S05
설정·인벤토리·정보·스킬·퀘스트·제조·강화·보스·퀵던전·캐시샵·이벤트를 기능 목록으로 유지한다. 미구현 기능의 활성 버튼을 배포 화면에 두지 않는다.
인벤토리
전체·장비·비장비 필터, 사용량·최대 칸, 칸 크기, 아이템 상세·사용·장착·해제·이동을 연결한다. 잠금·기간 만료·수량 부족 상태를 표현한다.
캐릭터 정보
장비, 이름·직업·레벨, 소속, 칭호·상징, 소개, 기본·추가 능력치, 상세 능력치, 기록을 구분한다.
스킬

퀘스트
메인·일반·직업·이벤트 분류, 진행 필터, 별표 추적, 최대 15개 제한, 포기 예외를 표현한다. 목표가 바뀌면 추적 UI도 갱신한다.

접속자·친구·길드·게시판·편지를 별도 기능으로 등록한다. 오프라인에서 실제 이용자 수나 서버 응답을 만들어 표시하지 않는다.

모든 목록 화면은 정상·빈 목록·잠금·조건 미달·데이터 오류 상태를 갖는다. 아이템 사용은 대상 선택 후 확정하고, 판매·버리기·강화는 실제 아이템과 비용을 보여 준다. 취소할 때 자원이 차감되면 안 된다.
설정에는 소리, 그래픽 품질, 진동, 입력 배치, 글자 배율, HUD 위치 초기화, 저장 정보, 종료를 둔다. 온라인 계정 기능을 넣을 때는 계정·서버 상태와 로컬 저장 상태를 구분한다.
시각 일치 검수는 창 테두리·재질·아이콘 의미·탭 순서·선택 상태·숫자 정렬·닫기 위치를 항목별로 실시한다. 임시 아이템과 뜻이 다른 캡처 아이콘은 교체해야 한다.

아이템과 경제 및 제작
재화의 유입과 소비를 연결하고 실패와 중복 처리까지 명시한다.
아이템 정의와 소유 인스턴스를 분리한다. 정의에는 종류·장비 부위·효과·중첩 한도·사용 조건·판매 정책·이미지를, 인스턴스에는 고유 ID·수량·강화·기간·잠금 상태를 둔다. 드롭·거래·우편·강화가 같은 인스턴스를 중복 생성하지 않게 한다.
시스템
규칙과 검수
재화
Gold와 라르 등 서로 다른 재화를 별도 장부로 관리한다[S05]. 획득·소비 원인과 변경 전후 잔액을 기록하고 음수·정수 초과를 차단한다.
상점
구매·판매·수량·가격·보유 공간을 거래 전에 검사한다. 보유 Gold와 공간 변경은 하나의 작업으로 저장한다.
전리품
드롭 테이블·소유권·수거 거리·소멸·가방 가득 참·바닥 중첩을 정의한다. 확률과 수량은 공식 자료나 검증 데이터로 확정한다.
제조
분류·레시피 해금·재료·Gold·성공 확률·실패 결과를 데이터로 둔다[S05]. 확률이 미확정이면 제작용 값임을 표시한다.
강화와 이전
에테르 강화 실패 보존 규칙과 같은 부위 이전 조건을 구현한다. 주문서 강화는 슬롯 개방 이후 100% 적용 규칙으로 분리한다[S05].
기간과 확장
기간형 가방 확장 만료 때 초과 아이템의 접근·회수 방법을 정의한다. 만료 때문에 보유물을 자동 소실시키는 동작을 임의로 추가하지 않는다.

경제 검토는 사냥 수입, 소모품 소비, 수리·제작·강화 지출, 레벨별 장비 접근 시간을 함께 본다. 시제품의 무제한 속성 변경·단일 무기 구매·정령 조각은 이 구조에 맞춰 정식 데이터로 교체한다.
유료 상품·거래소·확률형 판매는 로컬 데모의 가상 버튼으로 구현하지 않는다. 운영 단계에서 상품 원장, 지급·취소·복구, 가격·정책의 기준 버전, 서버 검증을 설계한 뒤 연결한다. 이 문서의 경제 수치는 원작의 미확인 가격이나 확률을 대신하지 않는다.

월드와 몬스터 및 던전
맵 배치와 전투 구성을 별도 데이터로 만들어 콘텐츠를 확장한다.
콘텐츠
제작 명세
필드와 마을
타일 크기·충돌·높이·가림·건물 출입구·NPC 위치·안전 구역·배경음·지도 라벨을 정의한다. 충돌 없는 장식과 통행 장애물을 구분한다.
지역 연결
출발 맵·출입 조건·도착 맵·도착 좌표·시선·이동 비용을 한 전환 규칙으로 둔다. 입장 실패는 원래 위치를 보존한다.
몬스터
종류·속성·HP·능력치·감지·추적·공격·기술·복귀·드롭·경험치·출현 조건을 데이터로 관리한다. 외형과 드롭 자료의 버전을 맞춘다.
행동 AI
대기·배회·발견·추적·공격·귀환·사망으로 나눈다. 장애물이나 경계에서 무한 추적·제자리 떨림·겹침이 생기지 않아야 한다.
던전과 보스
입장 조건·목표·실패·재입장·초기화·보상을 정의한다. 보스전의 광장·도전·기여와 주간 보상 구조는 별도 콘텐츠로 둔다[S05].
퀵던전
유리드에어리어와 모집·참가 흐름을 연결한다[S05]. 온라인 모집을 로컬 자동 입장으로 바꾸면 별도 모드로 표기한다.

레벨 디자인은 지형을 꾸미기 전에 이동 가능 그래프를 검수한다. 모든 출입구에 도달할 수 있고, 잘못된 좌표로 입장하지 않으며, NPC 대화 위치가 충돌 타일에 묻히지 않아야 한다. 원작의 지역 구조가 확보되면 현재 24×24 테스트 맵을 교체한다.
난이도 표에는 권장 성장 단계·적 구성·속성 대응·소모품 부담·회복 동선·실패 비용을 기록한다. 콘텐츠 소모 시간을 임의의 몬스터 체력 증가로만 늘리지 않는다. 보스의 예고·피해·회피 가능 타이밍은 동작 명세와 같은 이벤트를 참조한다.
콘텐츠 수락 기준: 입장부터 종료까지 막힘 없음, 귀환 가능, 보상 중복 없음, 지도와 실제 지형 일치, 적의 추적 종료 정상, 처치 후 출현 규칙 정상, 저장 재개 시 던전 상태 정책 일치.

온라인 기능과 운영 범위
싱글플레이와 원작 온라인 경험의 차이를 기능 단위로 관리한다.
원작은 동료 지원과 이용자 상호작용이 직업·경제·콘텐츠와 연결된다. 로컬 저장만으로 온라인 경험 전체를 동일하게 만들 수는 없다. 현재 빌드는 로컬 모험을 개발하고, 아래 기능은 서버를 포함하는 후속 단계의 요구로 보존한다.
기능
요구와 범위
계정과 캐릭터
인증·서버 선택·캐릭터 슬롯·생성·삭제·복구·중복 접속을 설계한다. 실제 넥슨 계정 또는 서버와 연결되었다고 표시하려면 정식 연동이 필요하다.
파티와 협동
초대·수락·탈퇴·리더·거리·버프·대상 선택·경험치·전리품 분배를 정의한다. 분배 공식은 원작 기준을 추가 확보한다.
친구와 길드
친구 최대 20명, 길드 정보와 순위 표시의 의미를 보존한다[S06]. 온라인 상태·차단·초대 실패를 서버 응답과 연결한다.
채팅과 게시판
채널·귓속말·차단·신고·게시 권한·입력 제한·검색·삭제 상태를 설계한다. 시제품에는 가짜 이용자 대화를 생성하지 않는다.
편지와 거래
편지에 아이템·Gold를 보내지 않는 규칙을 보존한다[S06]. 직접 거래·시장·보관함은 우편과 다른 원장·확정 흐름을 사용한다.
경쟁과 운영
PvP·길드전·랭킹·시즌·이벤트·운영 지급·장애 복구를 각각 정의한다. 매칭·보상·초기화 시점을 서버가 관리한다.

서버 단계의 최소 구조는 인증, 캐릭터 저장, 월드 처리, 인벤토리 원장, 채팅, 운영 도구다. 거래와 보상은 요청 ID로 중복 실행을 막고, 클라이언트가 보낸 잔액·피해를 그대로 신뢰하지 않는다.
운영 기획에는 업데이트 이력, 데이터 변경 검증, 공지, 문의 처리, 복구 기록, 접속 장애 대응, 이벤트 종료 처리를 포함한다. 실제 출시 국가·계정·결제 범위가 정해질 때 적용 정책을 다시 확인한다. 정식 온라인 운영을 이번 로컬 기획의 완료 조건으로 오인하지 않는다.

그래픽과 사운드 제작
원작 자산의 일관성과 게임 상태에 맞는 표현을 함께 검수한다.
제작 분야
자산 요구와 완료 기준
캐릭터
성별·헤어·색상·직업·장비와 방향별 클립을 관리한다. 무기·몸·머리·앞뒤 장비의 가림 순서를 실제 기준 장면으로 검수한다.
타일과 오브젝트
바닥·벽·건물·식생·문·출입 효과를 분리한다. 반복 경계와 높이 기준, 캐릭터 가림 규칙을 확인한다.
UI 자산
테두리·배경·아이콘·선택·비활성·누름 상태·폰트를 목록화한다. 서로 다른 기능에 같은 임시 아이콘을 돌려 쓰지 않는다.
전투 효과
시전·투사체·명중·회복·상태·사망·부활 효과를 개별 이벤트에 연결한다. 타격 판정과 빛 효과 시점의 차이를 기록한다.
사운드
지역 BGM, 발소리, 무기 공격, 피격, 주문, 창 열기, 아이템, 퀘스트, 사망음을 목록화한다. 중복 재생 한도와 거리·볼륨을 둔다.
설정과 접근성
BGM·효과음을 분리하고 음소거·진동·화면 효과 감소를 제공한다. 소리나 색 하나만으로 필수 정보를 전달하지 않는다.

자산 등록 정보는 ID, 출처, 기준 버전, 파일 해시, 원본 크기, 색상·알파 형식, 프레임 목록, 배율, 기준점, 사용 화면, 제작 상태다. 원본 파일은 수정본과 분리하고 빌드 자산 변환을 재현할 수 있게 한다.
픽셀 아트는 정수 배율 확대를 우선 검토하고 화면 축소 시 계단·흐림·글자 손상을 실기기로 확인한다. 카메라 좌표의 소수점 처리와 픽셀 정렬 정책을 통일한다. 발 기준점은 그림의 중심이 아니라 실제 지면 접점을 사용한다.
사운드는 자료를 직접 청취한 구간과 추정한 연출을 구분한다. 현재 영상 재생이 불가능했으므로 무기음의 길이나 주문 발동음을 확정하지 않는다. 발소리의 반복 주기는 걷기 프레임과 동기화할 수 있도록 데이터 필드를 준비한다.

개발 구조와 성능 목표
게임 규칙을 화면·입력·저장과 분리해 원작 데이터 교체 비용을 줄인다.
현재 GameState·GameRenderer·GameView 분리를 유지하되 World, Combat, Quest, Inventory, Progression, Animation, Audio, Save 서비스를 단계적으로 분리한다. 화면은 읽기용 상태를 사용하고 입력은 명령 큐로 전달한다. Android 생명주기와 시뮬레이션 시간의 소유자를 한 곳으로 통일한다.
기술 항목
요구와 측정 계획
데이터
규칙·콘텐츠·클립·UI 정의에 고유 ID와 스키마 버전을 둔다. 누락 참조, 중복 ID, 음수 비용, 순환 선행 퀘스트를 빌드 전에 검사한다.
저장
캐릭터·성장·장비·퀘스트·재화·HUD 설정을 원자적으로 저장한다. 이전 정상본 복구, 스키마 이전, 보상 수령 이력을 포함한다.
시간과 랜덤
단조 증가 시간과 명시적 난수 입력을 사용한다. 프레임 수를 피해·이동량으로 직접 쓰지 않는다. 앱 재개 시 시간 폭주를 막는다.
저사양 목표
초기 제안: 저사양 30fps, 상위 기기 60fps, 30분 전투 중 지속 메모리 증가 없음. 기준 기기와 장면을 정한 뒤 성능 예산을 확정한다.
렌더링
화면 밖 타일·개체 제외, 자산 재사용, 프레임별 객체 생성 축소, 이펙트 수 제한을 적용한다. 품질 변경은 판정 결과를 바꾸지 않는다.
배포 구조
디버그·검수·배포 설정을 분리한다. 버전·자산 해시·세이브 버전을 화면과 로그에서 확인하고 되돌릴 수 있는 릴리스 묶음을 보관한다.

성능 측정은 콜드스타트, 지역 이동, 다수 몬스터, 광역 마법, 인벤토리 반복, 저장, 백그라운드 복귀를 포함한다. 프레임 시간의 중앙값과 상위 지연, 메모리, 발열, 배터리를 기기별로 기록한다. 현재 목표 수치는 측정 결과가 아니다.
Android 빌드·실기기 실행은 아직 검증되지 않았다. 기존 데스크톱 검증은 순수 Java 규칙과 공통 렌더러 범위이며 Android Activity·Canvas·터치·설치 성공을 증명하지 않는다.

검수와 개발 실행 순서
기능 수보다 원작 일치와 끝까지 플레이 가능한 구간을 우선한다.
순서와 담당 역할
산출물과 통과 조건
1 기획·자료
기준 버전, 첫 지역, 퀘스트 원문, 정식 아이템·기술 목록, 움직임 영상 구간을 확정한다. 근거 없는 필수 값은 배포 데이터에 남기지 않는다.
2 클라이언트·아트
이동 보간·행동 상태·투명 스프라이트·발동 이벤트를 연결한다. 방향별 이동과 공격을 원작 기준 영상과 비교한다.
3 시스템 개발
생성·능력치·기술 비용·사망·슬롯·퀘스트 규칙을 교체한다. 중복 지급·저장 복구·실패 처리 검증을 통과한다.
4 콘텐츠·UI
실제 지역 한 구간에서 생성·대화·사냥·전리품·성장·보급·부활·재개까지 연결한다. 모든 화면의 빈 상태와 취소를 검수한다.
5 QA·빌드
APK 빌드와 설치, 저사양 기기 30분 플레이, 절전·강제 종료·복구, 폴더블·긴 화면 입력을 검증한다.
6 확장·운영
기준 구간 통과 후 직업·던전·상위 성장·온라인 시스템을 확장한다. 단계별 데이터 호환성과 복구 절차를 유지한다.

필수 회귀 시나리오: 이동 중 공격 연타, 사망 직전 물약, 동시에 발생한 처치·레벨 상승, 가방 가득 찬 드롭, 퀘스트 포기 후 재수락, 동일 보상 재요청, 저장 중 종료, 이전 버전 세이브, 잘못된 데이터, UI를 누른 채 앱 전환.
원작 비교 표에는 규칙·외형·타이밍·입력별 결과와 증거를 남긴다. 버그 심각도는 진행 불가·데이터 손실을 최우선으로 두고, 규칙 불일치, 입력 오류, 표현 오류 순으로 정리한다. 기획 변경과 구현 결함을 같은 상태로 처리하지 않는다.
일정은 자산 확보와 빌드 환경이 준비된 뒤 산정한다. 각 작업을 기획 확정·데이터 작성·코드·자산·검수로 나눠 소요량을 기록한다. 자료가 없는 모션까지 날짜를 단정하거나 전체 구현률을 임의의 퍼센트로 표시하지 않는다.
